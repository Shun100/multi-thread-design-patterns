# multi-thread-design-patterns

マルチスレッドのデザインパターン学習用

- C01 Single Thread Execution
  - 共有リソースに同時にアクセスできるスレッドを1つに制限する。
- C02 Immutable
  - 共有リソースの状態を変更できないようにする。
- C03 Guarded Suspension
  - 処理を実行するための条件が満たされるまで、スレッドを待機状態にする。
- C04 Balking
  - 処理を実行するための条件が満たされていなければ、スレッドを終了する。
- C05 Producer-Consumer
  - キューを通してデータのやり取りをすることで、ProducerとConsumerの処理速度の差を埋める。
- C06 Read-Write Lock
  - 共有リソースの読み取りと書き込みで異なるロックをかける。
    - 読み取りロック: 他スレッドも読み取り可能。書き込みは不可。
    - 書き込みロック: 他スレッドは読み取りも書き込みも不可。
- C07 Thread-Per Message
  - メッセージごとにスレッドを起動して並列処理する。
- C08 Worker Thread
  - スレッドを使いまわす。要するにスレッドプールのこと。
- C09 Future
  - 処理の完了を待たずに先に進み、処理結果が必要になったタイミングで結果を受け取る。
- C10 Tho-Phase Termination
  - スレッドに終了要求を送り、スレッド自身に後片付けをさせてから終了させることで、安全に終了させる。
- C11 Thread-Specific Storage
  - スレッドごとに独立したデータを保持する。
    - これだけだと当たり前にできることに聞こえるが、`ThreadLocal`を使うことで`static`変数もスレッドごとに異なる値を持てるようになる。
    - **まだ理解できていないので調査中**
- C12 Active Object
  - メソッドの呼び出しと、そのメソッドの実行を分離することで、非同期処理を実現する。
    - **まだ理解できていないので調査中**

## C01 Single Thread Execution

1. 概要

- 複数のスレッドから同じオブジェクトや共有リソースにアクセスする場合に、同時に実行できるスレッドを1つに制限する。

2. 目的

- データの不整合や競合状態を防ぎ、プログラムの整合を保つ。

3. 活用場面

- 銀行システム
  - 口座残高の更新
- 在庫管理
  - 商品の在庫数の増減
- チケット販売
  - 座席の重複予約防止
- ファイル操作
  - 共有ファイルへの書き込み
- キャッシュ管理
  - 共有キャッシュの更新

4. 実現方法

- `synchronized`や`Lock`

## C02 Immutable

1. 概要

- 一度生成したオブジェクトの状態を変更できないようにすることで、複数スレッドから安全に利用できるようにする。

2. 目的

- 複数スレッドから同じオブジェクトを安全に共有すること。
- オブジェクトの状態変更を禁止することで、データ競合を防止し、ロックによる排他制御を必要としないスレッドセーフな設計を実現する。

3. 利用場面

- ユーザ情報
  - ユーザID, 氏名, メールアドレス
- 設定情報
  - システム設定, 環境設定
- 商品情報
  - 商品ID, 商品名, 価格
- 日時情報
  - 日付, 時刻, タイムゾーン
- アプリケーションの状態
  - 初期化後に変更しない設定値

4. 実現方法

- `final`, `setter`を実装しない等

## C03 Guarded Suspension

1. 概要

- 処理を実行するための条件が満たされるまで、スレッドを待機状態にする。

2. 目的

- 条件が満たされていない状態での不適切な処理を防止する。
- 条件が成立するまでスレッドを待機させることで、CPUの無駄な消費を抑える。
- 複数スレッド間の処理タイミングを調整する。
- データの準備やリソースの確保など、処理の前提条件を安全に管理する。

3. 利用場面

- Producer-Consumer処理
  - キューにデータが追加されるまで消費側が待機する。
- データ受信処理
  - ネットワークからデータを受信するまで待機する。
- リソース管理
  - 利用可能なリソースが確保されるまで待機する。
- 初期化処理
  - 必要な初期化が完了するまで待機する。
- タスク管理
  - 実行対象のタスクが登録されるまで待機する。

4. 実現方法

- `wait()` + `notify()` / `notifyAll()`

## C04 Balking

1. 概要

- メソッドの実行時にあらかじめ定義された条件を確認し、条件が満たされていなければそのまま終了する。

2. 目的

- 処理を実行できない状態での無駄な処理や不適切な操作を防止し、システムの安全性と効率性を高める。
  - 実行条件を満たさない処理を防止する。
  - 不要なスレッドの待機を発生させない。
  - 同じ処理の重複実行を防止する。
  - オブジェクトの状態に応じて適切に処理を制御する。

3. 利用場面

- 初期化処理
  - 初期化済みの場合、再初期化を行わない。
- ファイル操作
  - ファイルが閉じられている場合、書き込みを拒否する。
- バックアップ処理
  - バックアップ実行中の場合、重複実行を防止する。
- バッチ処理
  - 既に実行済みの処理を再実行しない。
- 状態管理
  - オブジェクトが終了状態の場合、新しい処理を受け付けない。

4. 実現方法

- `synchronized` + フラグ変数

## C05 Producer Consumer

1. 概要

- データを生成する処理と、生成されたデータを利用する処理を分離し、共有キューを介して連携させる。

2. 目的

- 両社が独立したスレッドで動作するため、それぞれの処理速度やタイミングが異なっていても、効率的に連携できる。

3. 利用場面

- ログ処理
  - アプリケーションで発生したログをキューに格納し、別スレッドでファイルに書き込む。
- データ処理
  - データの取得処理と加工処理を別スレッドで実行する。
- メッセージ処理
  - メッセージをキューに登録し、Consumerが順次取り出して処理する。
- 画像・動画処理
  - 画像や動画のデータを取得する処理と、エンコード・変換する処理を分離する。
- Webサーバ
  - リクエストをキューに格納し、ワーカースレッドが順番に処理する。

4. 実現方法

- `BlockingQueue`

## C06 Read-Write Lock

1. 概要

- 読み取りと書き込みを区別して排他制御を行う。
  - 読み取りロック: 複数のスレッドが同時に取得できるロック。データの読み取りのみを許可する。
  - 書き込みロック: 1つのスレッドだけが取得できるロック。他のスレッドによる読み取り・書き込みを禁止する。

2. 目的

- 読み取り処理が多いシステムにおいて、読み取り性能を向上させる。

3. 利用場面

- 読み取り処理の頻度が書き込み処理よりも高い場面で利用する。
  - キャッシュ管理
    - 複数のスレッドがキャッシュデータを参照し、一部のスレッドがキャッシュを更新する。
  - 設定情報の管理
    - 複数のスレッドがアプリケーション設定を読み取り、管理スレッドが設定を変更する。
  - データベース
    - 負k数の処理がデータを参照し、一部の処理がデータを更新する。
  - ファイル管理
    - 負k数のスレッドがファイルの内容を読み取り、特定のスレッドがファイルを書き換える。
  - 共有データ管理
    - 複数のスレッドが共有オブジェクトを参照し、必要に応じてデータを更新する。

4. 実現方法

- `ReentrantRadWriteLock`

## C07 Thread Per Message

1. 概要

- メッセージやリクエストを受け取るたびに、それを処理する新しいスレッドを生成し、個別に処理を実行する。

2. 目的

- 処理の並行化
  - 複数のメッセージを同時に処理できるようにする。
- 応答性の向上
  - あるメッセージの処理が時間のかかる処理であっても、別のメッセージの処理を並行して進められる。
- 処理の独立性の確保
  - メッセージごとに処理を分離することで、各処理が互いに影響を与えにくい構造にする。
- 実装の単純化
  - メッセージごとにスレッドを割り当てるため、処理の並行化を比較的簡単に実現できる。

3. 利用場面

- Webサーバ、メールサーバ

4. 実現方法

- `new Thread()` + `start()` / `ExecutorService()`

## C08 Worker Thread

1. 概要

- あらかじめ用意した複数のワーカースレッドが、共有のタスクキューから処理対象のタスクを取得し、順次実行する。
- 一度タスクを処理した後もワーカースレッドは終了せず、次のタスクが登録されるまで待機し、別のタスクが登録されると再び処理を開始する。

2. 目的

- スレッドの再利用
  - 一度生成したワーカースレッドを繰り返し利用することで、スレッドの生成・破棄にかかるコストを削減する。
- リソースの効率的な管理
  - ワーカースレッドの数を制限することで、過剰なスレッド生成によるメモリやCPUの消費を抑制する。

3. 利用場面

- Webサーバ
  - 受信したHTTPリクエストをキューに登録し、ワーカースレッドが順次処理する。
- バッチ処理
  - 大量のデータ処理タスクをキューに登録し、複数のスレッドで並行処理する。
- 画像・動画処理
  - 画像の変換や動画のエンコードなどのタスクを複数のスレッドで処理する。
- メッセージシステム
  - 受信したメッセージをキューに登録し、ワーカースレッドが取り出して処理する。
- ファイル処理
  - ファイルの読み書きや書き込みなどのタスクを複数のスレッドで処理する。

4. 実現方法

- `newFixedThreadPool` + `BlockingQueue`

## C09 Future

1. 概要

- 時間のかかる処理を別スレッドで非同期に実行し、その処理結果を後から取得する。

2. 目的

- 処理の非同期化
  - 処理が終わるまで、呼び出し元のスレッドをブロックしないようにする。
- 処理効率の向上
  - 処理の待ち時間を利用して、別の処理を並行して実行できるようにする。

3. 利用場面

- 時間のかかる計算処理
  - 大量のデータ集計、複雑な数値計算
- ファイル処理
  - 大容量ファイルの読み込み、書き込み
- ネットワーク通信
  - Web APIへのリクエスト、データ取得
- 複数処理の並列実行
  - 複数のデータソースから同時に情報を取得
- バックグラウンド処理
  - 画像の変換、データ圧縮

4. 実現方法

- `ExecutorService` + `Future`

## C10 Two Phase Termination

1. 概要

- スレッドを強制的に停止するのではなく、終了要求を通知し、スレッド自身が適切なタイミングで処理終了を行ってから停止するようにする。

2. 目的

- 安全にスレッドを終了する。

3. 利用場面

- バックグラウンド処理
  - 定期的にデータを監視するスレッドの終了
- サーバーアプリケーション
  - サーバー停止時の各処理スレッドの終了
- ファイル処理
  - ファイルの読み書きが完了してからファイルを閉じる
- データベース処理
  - 処理中のトランザクションを適切に終了する
- 定期実行処理
  - 一定間隔で動作する管理・ログ収集スレッドの終了

4. 実現方法

- `volatile`, `shutdown()` / `shutdownNow()`等

## C11 Thread Specific Storage

1. 概要

- 複数のスレッドが同じオブジェクトや処理を共有しながら、それぞれスレッド固有のデータを個別に管理する。

2. 目的

- スレッド間のデータ競合を防止する
  - 各スレッドが独立したデータを保持するために、ほかのスレッドによるデータの変更を気にしなくて済む。
- 排他制御の負担を軽減する
  - データをスレッドごとに分離することで、共有データへのアクセス時に発生するロックやミューテックスなどの排他制御を減らせる。
- スレッド固有の状態を管理する
  - 各スレッドの処理状況や設定値などをスレッド単位で保持できる。

3. 利用場面

- データベース接続の管理
  - スレッドごとに異なる接続を保持する
- ログ出力
  - スレッドごとにログ情報やログ出力先を管理する
- エラー情報の管理
  - スレッドごとにエラーコードやエラー内容を保持する
- 一時データの管理
  - スレッドごとに処理中の一時変数やバッファを保持する
- リクエスト処理
  - Webサーバなどで、スレッドごとにリクエスト情報を保持する

4. 実現方法

- `Thread Local`

## C12 Active Object

1. 概要

- オブジェクトへのメソッド呼び出しを別のスレッドで実行する仕組みを提供する。
- 通常のオブジェクトでは、メソッドを呼び出すと、その呼び出し元のスレッドで処理が実行される。
- 一方で、Active Objectパターンでは、メソッドの呼び出しを要求として受け取り、専用のスレッドがその要求を処理する。
- 呼び出し元のスレッドと処理を実行するスレッドが分離されるため、呼び出し元は処理の完了を待たずに、次の処理へ進むことができる。

2. 目的

- 処理の非同期化
  - メソッドの実行を別スレッドに任せることで、呼び出し元の処理をブロックせずに実行できる。
- 並行処理の実現
  - 複数の処理要求を受け付け、専用スレッドで順次処理することで、ほかの処理と並行して動作できる。
- スレッド間の依存関係の軽減
  - 呼び出し元のスレッドと実行側のスレッドを直接連携させず、要求を介して処理を依頼できる。
- 共有データへのアクセス制御
  - 専用スレッドが対象オブジェクトの処理を担当することで、複数スレッドから同時にアクセスされることを防ぐ。

3. 利用場面

- GUIアプリケーション
  - 時間のかかる処理をバックグラウンドで実行する
- ネットワーク通信
  - データ送信や受信処理を別スレッドで実行する
- ファイル処理
  - 大容量のファイルの読み込みや書き込みを非同期で実行する
- データベース処理
  - データベースのへの更新要求をキューに登録して順次処理する
- サーバーアプリケーション
  - クライアントからの処理要求を受け付け、バックグラウンドで処理する

4. 実現方法

- 複数のクラスを組み合わせて実現する。(そのため、マルチスレッドデザインパターンの中でも最も複雑な構成)
  - Proxy
    - 呼び出し元からメソッド呼び出しを受け付け、要求を生成する
  - Method Request
    - 実行する処理を要求オブジェクトとして表現する
  - Activation Queue
    - 実行待ちの要求を格納するキュー
  - Scheduler
    - キューから要求を取り出して実行する
  - Servant
    - 実際の処理を実行する
  - Future
    - 非同期処理の結果を後から取得する

## 各デザインパターンの実装方法

| No  | デザインパターン          | 実装方法                                          |
| --- | ------------------------- | ------------------------------------------------- |
| 1   | Single Threaded Execution | `synchronized`                                    |
| 2   | Immutable                 | `final`クラス・フィールド                         |
| 3   | Guarded Suspension        | `wait()` / `nottifyAll()`                         |
| 4   | Balking                   | 条件判定と同期                                    |
| 5   | Producer-Consumer         | `BlockingQueue`                                   |
| 6   | Read-Write Lock           | `ReentrantReadWriteLock`                          |
| 7   | Thread-Per-Message        | `newVirtualThreadPerTaskExecutor()`               |
| 8   | Worker Thread             | `newFixedThreadPool()`                            |
| 9   | Future                    | `ExecutorService.submit()` / `Future`             |
| 10  | Two-Phase Termination     | `shutdown()` / `shutdownNow()`                    |
| 11  | Thread-Specific Storage   | `ThreadLocal`                                     |
| 12  | Active Object             | `newSingleThreadExecutor()` / `CompletableFuture` |

## 実装方針

1. ExecutorServiceを基本とする

- スレッドの直接生成・管理を避ける。
- タスクの実行とライフサイクル管理を分離する。
- `try-with-resource`によるリソース管理を活用する。

2. モダンなJava APIを使用する

- Producer-Consumerには`BlockingQueue`を使用。
- Thread-PerMessageにはjava 21の仮想スレッドを使用。
- Active Objectには`CompletableFuture`を使用。

3. スレッドセーフティを考慮する

- `wait()`後の条件再確認には`while`を使用。
- ロックは`try-finally`で確実に解放。
- `ThreadLocal`はタスク終了時に`remove()`する。
